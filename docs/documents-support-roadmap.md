# Broiler.Documents support roadmap for Broiler.Writer

Audit date 2026-11-16. Baseline Writer `6c27f09`, Documents checkout `2b0d736`, and UI checkout `12eed03`. This is an implementation roadmap from source and package inspection. The existing Writer suite passed all 290 tests on Windows. The feature-specific fixtures and cross-platform checks below are proposed acceptance tests.

Spreadsheet support belongs to Broiler.Cells.

## What Writer can use today

| Capability | Writer baseline | Remaining gap |
| --- | --- | --- |
| RTF, DOCX, ODT, HTML, Markdown | Open and save on Windows, Linux, Android and WebAssembly. The selected codec decides format fidelity. | Display and author more of the imported model. Report loss before a save or conversion. |
| PDF | Windows and Linux import with password handling. WebAssembly imports with browser limits and no password prompt. Android has no registration. The three import heads compose managed image, font and color-profile services. | Android import, browser credential retry, and gated PDF export. Import produces editable content with approximations. |
| Print | Windows, Linux and Android use Documents pagination. Linux also uses the raster PDF spool writer. Android enters the system print flow. WebAssembly has no print host. | Bring paginated viewing to editing and add a browser print host if platform requirements can be met. |
| Core editing | Basic font and decoration controls, alignment including justification, simple lists and indent, inline picture insertion, undo/redo, and break insertion through Formatting Codes. | Rich formatting controls and structural editing. |
| Formatting Codes | Documents projects model ranges into tokens. Writer navigates, edits and removes a subset. The visible Insert Code menu offers four character styles and tab, soft line, paragraph and page breaks. The controller also handles property edits such as color, links and spacing. | Add controls and tokens alongside the underlying edit operations. Show a property safely when it has no supported mutation. |

The [shared format registry](../src/Broiler.Writer/WriterDocumentFormats.cs) serves native Writer. The browser uses a [separate catalog and application shell](../src/Broiler.Writer.WebAssembly/BrowserWriterDemo.cs). The [browser PDF guide](browser-pdf-support.md) reflects browser support that the repository README’s format summary omits.

Forced restore evaluation across all four heads and the test solution resolves Documents to **preview.32**, commit `99d5ac894707aa3878777c45660c706605f7c0ed`, and RichEdit to **preview.29**, commit `65e05fab81c8ff1dfe7287421d16c472abd1f927`. These commit IDs come from the restored package manifests. The corresponding RichEdit source directories have no committed diff from the package commit to the inspected UI checkout. The [central package file](../Directory.Packages.props) uses one overridable Documents version. Its prior Model property said preview.31, while NuGet already selected preview.32. Before and after consolidation, the PDF codec was present in Windows, Linux, WebAssembly and the test project. Features visible only after `99d5ac8` in Documents are upgrade candidates.

The checkout adds baseline shift and language to inline runs, and heading level, paragraph borders, RTL direction, drop caps, soft break hints and grid-related settings to paragraph styles. It also contains newer image and shape layout, numbering, and running-content work. Check each proposed acceptance fixture against both the currently consumed package and the candidate package. Updating just the codec can deliver parsing improvements while the same property still needs live layout and editing work in RichEdit.

## Formatting and structure inventory

“Display” here means the live RichEdit surface. Printing uses a separate layout path. A property can survive import and save even when RichEdit draws a simplified representation. Preservation must be measured per codec and operation.

| Family | Documents capability and Writer gap | Roadmap |
| --- | --- | --- |
| Character formatting | The Format menu and Formatting Codes support capitalization, text color, highlight, and link editing. Writer reports imported hidden text in its editing-view notes. Hidden-text editing still needs coordinated visibility, caret and selection behavior. Newer Documents adds language, baseline shifts, symbol handling and form-related run flags. | M1, M2, M5 |
| Paragraph formatting | The default build edits spacing, line height, indents, shading, uniform borders, aligned tabs, outline levels and reusable paragraph styles. RichEdit uses these values in its continuous layout. RTL, drop caps and grid controls are scheduled separately. | M2, M3, M5 |
| Numbering | Writer uses Documents list identities and `ListNumberer` for markers and exposes level, restart, continue and hanging indent controls. | M2, M5 |
| Pages, breaks and sections | Page Layout shares its paginator with print and supports direct editing of horizontal body text. Writer edits document and section paper settings, section breaks, columns, keep rules, and widow/orphan rules. | M3, M5 |
| Headers, footers and fields | Page Layout and print evaluate running content per page. Writer edits plain and formatted default, first-page, and even-page bands, links individual bands to the preceding section, and inserts page number, page count, and named paragraph style references. DOCX preserves live links. | M3, M5 |
| Tables | Existing RichEdit lays out imported tables with nested content, spans, shading and borders. It uses a simplified grid and padding path. Documents has topology, row/column operations, more sizing and positioning metadata, repeat headers, row-height/split policy, and per-cell presentation. Writer lacks table-specific structural commands. | M4 |
| Pictures, shapes and wrapping | Writer edits inline picture properties and supported floating pictures, shapes and text boxes through Graphics and Page Layout, with paginated selection handles and source-aware running-object editing. Complex frames, advanced geometry and format-specific preservation limits remain bounded as described in M4/M5. Newer Documents extends shape/image properties and layout behavior. | M0, M4, M5 |
| Notes and revisions | Documents models footnotes/endnotes, numbering and text revisions. Pagination handles note placement and has revision-aware rendering paths. Writer has no note-body editing or review workflow. The existing Document Notes dialog displays codec diagnostics. | M3, M5 |
| Forms and imported fallbacks | New Documents run flags distinguish form elements/controls and shape text. Retain their supported imported representations and surface approximations. Interactive form authoring, complex field evaluation and embedded objects require format/model decisions first. | M0, M5 |

### M1 — Character formatting and links

1. **Delivered in Writer.** The native and browser Format menus provide all caps, small caps, text color, highlight, and link editing. Color dialogs take RGB values and clear each color independently. Capitalization and colors apply to a mixed selection or to new text at the caret. The link dialog edits the display text and target, reports mixed targets, removes links, and opens a single external target through the native or browser host. Link targets can be changed across paragraphs without replacing the selected text or paragraph breaks. RTF, DOCX, ODT, and HTML reopen with capitalization, colors, and external links intact. Markdown preserves external links and reports capitalization and color losses before interactive save or export.
2. **Hidden text.** The source candidate has an undoable Format command for the selection or typing caret and a separate **View → Show hidden text** toggle. Suppressed runs use zero width and retain their source ranges. Arrow navigation skips their interior when hidden. Selection and copy include source text, while print omits hidden runs independently of the view toggle.
3. **Superscript, subscript, and language.** The source candidate applies all three to the selection or typing caret. RichEdit measures and draws shifted runs, reserves vertical room for explicit shifts, and uses the run language for display casing. DOCX and ODT reopen the tested language, hidden text, and script together. Conversion review identifies file formats that lose these properties. Recovery verifies language and baseline on readback and retries with DOCX when RTF loses them.
4. **Formatting Codes and named character styles.** Capitalization, colors, links, and the advanced run properties have typed edits and source ranges with undoable removal. DOCX and RTF preserve the tested character-style name and resolved appearance. Reusable definitions still require a catalog that preserves which properties come from the style and which are direct formatting. Use that catalog to implement applying, editing, and persisting definitions.

**Qualification.** The default build includes advanced character formatting. Run [the Documents candidate script](../eng/test-documents-candidate.ps1) with a Documents checkout, a fresh output directory, and a package version to test a candidate against the same Writer features. Named style definitions remain open.

### M2 — Paragraph styles, tabs and numbering

1. **Paragraph properties.** Native and browser Writer edit spacing, proportional and fixed line heights, indents, shading, and a uniform solid border. RichEdit measures line boxes with the model’s height rules and converts points at the current zoom. Imported border patterns are drawn as solid edges in the editing view.
2. **Tab stops.** Writer edits left, center, right, and decimal stops and their leaders. Painting, wrapping, selection and hit testing use the same tab calculation. Regression fixtures exercise zoom, decimal alignment, an empty paragraph and a table-cell origin.
3. **Numbering.** Writer can create, continue, restart, and remove lists, choose their marker format, change levels, and specify a hanging indent. RichEdit uses `ListNumberer`. Splitting an item, including insertion of plain text with breaks, carries the list identity without repeating the item’s restart. DOCX saves a top-level restart as another numbering instance and reports a loss for nested restarts. ODT keeps item start values.
4. **Heading semantics and styles.** Writer edits outline levels separately from visual presets. **Format → Paragraph → Named styles** can save the selected paragraph’s properties and default typography, apply a definition, update it, or detach it. Updates propagate to paragraphs that use the style and retain direct overrides. DOCX and ODT carry named definitions, including unused ones, and paragraph associations. Imported style inheritance is resolved into reusable definitions. Save and recovery compare reopened definitions, paragraph properties and list markers.

**Qualification.** The default build includes these controls. The suite compares exact line height and all four tab alignments in live view and print using two fonts, four margins and zoom levels, and compares list markers across restarts and interruptions.

### M3 — Paginated viewing and page structures

**Default-build rollout complete.** Writer uses Broiler.Documents preview.34 and Broiler.UI preview.33. Page and document edits use RichEdit’s public transaction methods.

1. **Available in the default build.** View → Page Layout shows the committed snapshot using the print paginator, with page navigation and the document's paper setup. Print can supply its own paper and orientation overrides.
2. Click horizontal body text to place the caret at a character boundary, including case-only display transformations. Shift-click extends the selection across lines, columns, or pages. Type on page sends text and editing keys through RichEdit and repaginates after changes. Up and Down follow the rendered body lines, and Shift extends the selection. IME preedit is drawn at the paginated caret until committed or cancelled. The visible page's rendered text is exposed through the desktop semantic tree and the browser's accessibility region. Edit text and Go to body open the selected range in a continuous editor.
3. Set page size, orientation, margins, header/footer distance, and column geometry for the document or current section. Insert or change a section break, restart and format page numbers, and set paragraph keeps, widow/orphan counts, and page, column, or soft page breaks. ODT keeps leading hints in body paragraphs, list items, and before eligible inline table rows. It also retains the inline markers that determine the saved page sequence, including markers inside cells. Changes enter the normal undo history.
4. Edit headers and footers by section and page variant. Link a band to the preceding section or unlink it to keep a local copy. Use `{page}`, `{pages}`, and `{style:Style name}` for fields evaluated by the paginator. DOCX preserves live links, named paragraph style fields, and section numbering formats. The rich-text dialog supports multiple paragraphs and inline formatting. Save review reports lost links and changes to page settings, including imported soft page hints.

The three-section test covers first/default/even bands, restarted Roman numbering, explicit column and page breaks, a keep-with-next paragraph, and navigation back to the source paragraph. It compares page count and drawn text across Page Layout and print and checks the source bounds reported by pagination.

**Known limits and follow-up.** Cell interiors and row boundaries that cross merges or keep rules lack soft-break authoring. Complex table fragments and richer running-band editing follow the M4 table and shape controls. Length-changing transformations and bidirectional or vertical text still need character geometry. Platform screen-reader and native IME verification remains open.

### M4 — Tables, pictures and shapes

1. **Complete for the initial table editing surface.** The native and browser Table menu inserts and deletes tables, inserts and deletes rows and columns, selects cell, row, or table content, navigates cells, merges a rectangle, splits a merged cell, and edits column width and minimum or exact row height. Tab and Shift+Tab navigate the existing cells and move out of the table at its boundaries. `DocumentTableTopologyAdapter` resolves merged roots, structural selections, and cell-padding hits in Page Layout. Each change uses the published `RichTextEditor.ApplyDocumentEdit` transaction, so undo restores text, grid, selection, and document metadata together.

   Structural edits currently apply to top-level inline tables with complete paragraph ranges and no nested or specialized cell data. Row and column insertion/deletion and rectangle merges require an unmerged rectangular grid. Splitting restores the merged grid slots, retains the merged text in the first cell, and creates empty paragraphs for the other slots. Existing nested and merged tables support cell navigation. Item 2 adds presentation and sizing edits for them; count-changing structural edits retain the restrictions above.

   Tests cover native commands, Tab navigation, touch targeting of cell padding, insertion between populated columns, partial-rectangle text reordering, shape and section anchor updates, exact-height DOCX output, merged ODT output, and undo. Save review compares reopened table cell content and spans.
2. **Implemented in Writer and the sibling UI/Documents source; package integration pending.** The native and browser Table menu now exposes Cell properties, Cell borders, Table properties and Row properties. Cell formatting applies to the current cell or the rectangle between the selection endpoints, resolving merged roots once. It supports independent left/top/right/bottom padding (or inherited table padding), top/center/bottom alignment, RGB shading or none, and individual/all edges with none, solid, dashed, dotted, double, groove, ridge, inset or outset borders. Table properties expose automatic/point/percentage preferred width, start/center/end alignment, autofit, left indent and keep-together. Row properties set leading repeated headers, split policy and keep-with-next. Column width and minimum/exact row height also work in nested and merged tables. Formatting preserves cell content, nesting and model metadata and is one undo transaction per Apply.

   Shared `Broiler.UI.RichEdit.Standard` continuous layout now uses per-cell padding, vertical alignment, preferred/percentage widths, alignment, indentation, content-based autofit and parent-relative nested sizing. Minimum-height rows grow; exact-height rows clip overflowing glyphs, backgrounds, selections, IME composition and carets while retaining all text. Covered cells are not laid out twice. Spanning cells use their complete row extent. Styled borders scale with zoom; conflicts resolve once per shared edge segment, including seams beside row spans. Hit testing uses the same cell and text geometry. Pagination-specific repeats, split rules and keep rules are applied by the existing Documents paginator in Page Layout and print, rather than simulated on the continuous sheet.

   Header boundaries cannot bisect a vertical merge, and new vertical merges cannot cross a header boundary. Inserting between leading header rows retains their header status. Presentation and sizing edits are enabled on nested/spanning tables without rebuilding their topology; row/column count changes and merges retain item 1's validated structural subset. This is an intentional limit, not a claim that arbitrary nested or merged-table surgery is supported.

   Save review now compares cell presentation, table sizing, row behavior and nested formatting as well as topology/text, allowing small codec unit-rounding differences and equivalent explicit grid widths. The new round-trip tests exposed an ODT writer omission: the sibling Documents source now emits leading rows inside `table:table-header-rows`, with a write/reopen regression test. Published Documents preview.34 still loses these headers. Other codec limits remain visible through save review: for example, preview.34 does not preserve the table autofit flag or DOCX table-level keep-together/row keep-with-next settings. These controls edit the model and affect supported pagination; they do not promise unsupported same-format persistence.

   Validation: 391 Writer tests pass with published UI preview.30 and with `UseBroilerUiSource=true`; 341 shared RichEdit tests and 813 ODT tests pass. Coverage includes selected-cell formatting and undo, DOCX/ODT presentation round trips, nested sizing, repeated-header pagination/print, rowspan boundary rejection, exact-height clipping, zoomed autofit, covered cells and segmented border conflicts. Windows Release builds and a trimmed WebAssembly publish succeed with the UI source. A Chromium check exercised all four dialogs and visually verified centered sizing, cell shading and a double border.

   **Release integration:** publish updated Broiler.UI and Broiler.Documents packages from these sibling changes, then update Writer's pins. Default builds use UI preview.33 and Documents preview.34. The new controls and save-review checks compile and run with those packages; the continuous-layout improvements and ODT header-writing fix require the corresponding new packages. For local UI validation use `-p:UseBroilerUiSource=true`.
3. **Implemented in Writer; Documents anchor fixes await package rollout.** The shared native/browser Graphics menu adds picture properties, intrinsic-size restoration, floating-picture conversion, rectangle/ellipse/text-box insertion, object selection/deletion, placement, wrapping and rich text-box editing. Picture properties edit width/height, alternative text and independent rectangular crop percentages. Changing one dimension with aspect lock enabled computes the other; invalid crops cannot remove the entire source. Intrinsic sizes use the image resource's pixel dimensions at the model's 96-dpi conversion. Aspect lock is an editing preference for the editor session, not a new persisted format attribute. Editing one inline occurrence does not change another occurrence that shares its image. Resource IDs, payloads and resource-policy decisions remain attached to the edited picture.

   Object placement exposes X/Y, width/height, paragraph and column-relative anchors, paragraph anchors measured vertically from page top, physical-page anchors, behind/in-front-of-text placement and stacking order. Wrapping exposes none, square and top-and-bottom modes, left/right/largest text side and clearance. Repeated header/footer objects retain their running-story anchor; moving them updates the shared source and every occurrence, including paragraph-relative band offsets. Complex rotated/grouped objects, as-character/source-inline frames, linked chains and frames with automatic width/fitting retain their model data and have restricted editing. New text boxes support multiple paragraphs and the shared bold/italic/underline editor.

   Page Layout now has Edit objects and Properties controls. Eight handles support mouse/touch movement and resizing using the actual paginated bounds. A drag is provisional until release and creates one undo transaction; Escape or touch cancellation discards it. Arrows move, Alt+arrows resize, Shift uses ten-point steps, Tab/Shift+Tab select objects and reveal their page, Page Up/Down navigate pages, Enter opens properties, Delete removes the selected supported object, and Ctrl+Z undoes. Read-only documents allow selection without mutation. Object names/alt text and selection state are exposed in the page semantics. Selection handles are suppressed while a nested properties dialog is open. The disposable editing scene maps rendered occurrences back to their original immutable source objects without changing saved stacking values. Page-, column- and repeated-header coordinates come from the paginator, and wrapping continues to use the shared Documents exclusion geometry.

   Graphics save review and recovery validation now compare object count, anchors, placement, dimensions, relative stacking, wrap settings/clearances, text-box text and picture size/alt/crop metadata. Missing or blocked payloads receive an editing-view diagnostic and an explicit message in Picture properties. Codec limitations are reported: current ODT drops rectangular crop metadata, and DOCX cannot retain a physical page-number anchor. The controls do not claim those formats can persist properties their codecs do not support.

   Testing found two upstream defects, both fixed in the sibling Documents source: paragraph insertion/deletion now moves body-shape anchors with their surviving paragraphs inside the original undo transaction, and DOCX writing retains the distinction between column-relative and text-area-relative horizontal anchors while preserving cell-relative line behavior. Published Documents preview.34 still has the old behavior; Writer reports its anchor-tracking limitation. A new Documents package and updated Writer dependency pin are required to ship these fixes. Item 3's controls and paginated object editing work with the currently published UI/Model APIs; the pending UI publication from item 2 remains separate.

   Validation: 403 Writer tests pass against the published dependencies; 409 pass against the locally packed Documents candidate plus UI source and advanced-character coverage. All 424 Model and 1,221 DOCX tests pass. Tests cover selected/shared inline images, intrinsic restoration, aspect resizing, invalid crops, rich text boxes, mouse/touch move/resize/cancel and undo, read-only behavior, nested properties, actual second-column and physical-page placement, repeated-header source editing, split/reanchor/undo/save/reopen/print, DOCX crop persistence and explicit ODT crop-loss review. Windows Native AOT and trimmed WebAssembly publishes succeed. Chromium exercises insertion, placement, wrapping, page dragging/resizing and the nested properties dialog.

Exit with keyboard and touch table navigation, undoable merge/split and resize, and same-format preservation tests for varied spans. Verify a wrapped picture and text box survive moving an anchor across a paragraph split, undo, save, reopen and print. Confirm denied or unavailable image resources receive a clear diagnostic.

### M6 — PDF and platform output

1. **Android import.** Compose the codec only in the Android head. Validate URI input, retry/cancel behavior, file and decoded-image limits, memory budget, font/color service composition and managed publish size. Open a text PDF and an image PDF, then save each to an editable format.
2. **Browser credential retry.** Reuse the native password support semantics with a bounded browser retry buffer and transient credential lifetime. Keep current content intact on cancellation or invalid passwords. Test a successful retry, repeated invalid credentials and permission denials under the browser caps.
3. **PDF export.** Keep the export entry point gated on the upstream write-preview milestone. Connect export to the paginator and PDF preflight, with Unicode/font embedding, image policy, links, permissions and output limits checked before commit. Use staged destination replacement or complete browser downloads. Require independent extraction, rendering and structural validation as specified upstream. Keep Linux’s spool PDF path available for printing. [PDF delivery gates](../../Broiler.Documents/docs/roadmap.md#pdf-delivery-gates) · [Writer and output integration](../../Broiler.Documents/docs/roadmap.md#writer-and-output-integration-phase-7)
4. **Browser print.** Design a browser host around the previewed page artifacts and browser print lifecycle. Test page range, orientation, cancellation and input/output limits in the trimmed WebAssembly build. Treat OCR, exact PDF page editing and restricted-document behavior as separately gated upstream tracks.

## Release checks

- For each feature, record import, live display, authoring, save/reopen, conversion, and print status separately. Mark a surface verified only after running its acceptance test. Keep per-format outcomes tied to the exact codec version.
- Exercise open → save, open → unrelated edit → save, edit → undo/redo, paste, and recovery where the platform ships it. Check nested stories and resource grants as well as plain text and root properties.
- Run the Writer suite and clean platform builds for Windows, Linux, Android and WebAssembly. Run desktop NativeAOT and trimmed WebAssembly publishes when the dependency graph changes. Use cross-platform font-pinned image tests alongside structure assertions and native keyboard/touch smoke tests.
- Test page layout with identical font inputs and page settings. Supplement visual comparisons with caret/selection bounds and page/column membership. Use representative long documents to record cold open, edit, relayout and memory against the previous release.
- Ship user-facing format labels, limitations and diagnostic wording with the implementation. Update the README format matrix, browser behavior and platform picker coverage together.
